# 화면 개발 가이드 (Thymeleaf)

화면설계서·화면캡처를 Thymeleaf 템플릿으로 옮길 때의 규칙입니다.

## 2. 모바일 기준

사용자·관리자 모두 **모바일(430 × 932) 기준**으로 설계한다. 폭 480px 이상(PC·태블릿)에서는 화면 가운데에 폰 프레임으로 표시된다.

- 사용자(반응형): 모든 기기에서 화면을 **설계 폭 430px** 로 그리고 `user-layout.html` head 스크립트가 배율(`--frame-zoom`)과 높이(`--app-h`)를 정한다.
  - 휴대폰(폭 480px 미만): 기기 폭에 꽉 차게 확대·축소, 높이 = 기기 높이 ÷ 배율 → 360·375·390·412px 어느 기기든 같은 비율로 보인다.
  - PC·태블릿: 430 × 932 프레임, 창이 작으면 비율을 유지한 채 축소.
  - 따라서 CSS 는 항상 폭 430px 기준으로 쓴다. 기기 크기 `@media (max-width/max-height)` 대신 프레임 기준 `@container app (max-height: …)` 를 쓴다 (예: 높이가 짧은 기기 보정).
- 사용자: `.app-shell` 이 프레임이 되고 안쪽 `.screen` 이 스크롤된다. `position: fixed` 요소(하단 탭·바텀시트·하단 버튼)는 프레임 안에 고정된다. 전체 높이는 `100dvh` 대신 `var(--app-h)`, 폭은 `100vw` 대신 `100%` 를 쓴다. 레이어·바텀시트는 반드시 `.app-shell` 안에 둔다.
- 관리자: `admin-layout.html` 의 `#adminFrame` (최대 430px)이 프레임이다. 레이어는 `absolute` 로 프레임 안에 둔다.
- **화면 크기 단위는 `vw`·`vh`·`dvh` 를 쓰지 않는다.** PC에서는 이 단위가 프레임이 아니라 브라우저 창 전체(예: 1920px) 기준이라 크기가 디자인과 달라진다. 사용자 화면은 `.app-shell` 이 컨테이너이므로 `cqw`(프레임 폭의 1%)·`cqh`(프레임 높이의 1%)를 쓰고, 관리자 화면은 px·% 로 쓴다.
- 화면 확인은 휴대폰 크기(430 × 932)와 PC 크기(예: 1920 × 1000) 둘 다에서 한다.

## 3. 폴더 구조

```text
src/main/resources/
├── templates/
│   ├── fragments/
│   │   ├── user-layout.html     # 사용자: head, header, bottomNav, back, brandMark, scripts
│   │   ├── admin-layout.html    # 관리자: layout(헤더 + 콘텐츠 + 하단 탭)
│   │   └── admin-overlays.html  # 관리자: 전체 메뉴·통합 검색·알림 패널
│   ├── user/                    # 사용자 화면 (화면 그룹별 하위 폴더 가능)
│   └── admin/                   # 관리자 화면
└── static/
    ├── css/user/app.css         # 사용자 공통 (프로토타입 기반)
    ├── css/user/<그룹>.css       # 사용자 화면 그룹별 스타일 (캡처와 맞추는 보정 포함)
    ├── css/admin/admin.css      # 관리자 공통 (나머지는 Tailwind 유틸리티 클래스)
    ├── js/user/app.js, js/admin/admin.js   # 공통 동작
    ├── js/user/<그룹>.js, js/admin/<그룹>.js
    └── images/user/*.svg|png, images/admin/icons.svg (아이콘 스프라이트)
```

- 사용자 화면: 프로토타입 CSS 클래스(`app.css`)를 그대로 사용하고, 캡처와 다른 부분은 **그룹별 CSS에서 덮어쓴다** (`app.css` 직접 수정 금지).
- 관리자 화면: Tailwind 유틸리티 클래스(개발용 CDN). 아이콘은 `<svg class="icon" width="20" height="20"><use th:href="@{/images/admin/icons.svg} + '#i-bell'"/></svg>`.
  사용 가능한 아이콘: arrowRight alert bell calendar camera chat check chevron coin document edit home clock help menu people pin refresh search send settings star truck trash user robot x

## 4. 공통 동작 (data 속성)

| 속성 | 동작 |
| --- | --- |
| `data-open="#id"` | 레이어(바텀시트·팝업) 열기 |
| `data-close` | 가장 가까운 `[data-layer]` 닫기 (`data-close="#id"` 로 대상 지정 가능) |
| `data-layer hidden` | 레이어 요소. `hidden` 상태로 시작 |
| `data-tabs` / `data-tab="x"` / `data-panel="x"` | 탭 전환 (사용자: `.active`, 관리자: `.is-active` 토글) |
| `data-back="true"` | 사용자 뒤로 가기 |

화면 고유 동작(단계 이동, 품목 수정, 필터 등)은 그룹별 JS에 작성한다.

### 쉬운 모드 (사용자)

일반 모드와 **같은 URL·템플릿**을 사용하고, 상단 일반/쉬운 토글로 전환한다 (localStorage 유지).

| 방법 | 용도 |
| --- | --- |
| `.easy-mode .xxx { ... }` | 글자·버튼 크기 등 스타일 차이. `app.css`의 `.easy-mode` 변수(`--text-body` 등)가 자동 적용된다 |
| `data-easy-only` / `data-standard-only` | 모드별로 내용이 다른 부분 (예: 쉬운 모드 전용 홈, 음성 안내 버튼) |
| `data-easy-class="cls"` | 쉬운 모드일 때만 클래스 추가 |
| `CodeMove.mode()`, `codemove:mode` 이벤트 | JS에서 모드별 문구 교체 등 |

확인할 때는 URL에 `?mode=easy` 를 붙인다 (예: `/?state=none&mode=easy`).

## 5. 화면 상태와 더미 데이터

- 화면 개발 단계에서는 **더미 데이터를 템플릿에 직접 작성**한다 (캡처의 문구·숫자 그대로).
- 캡처마다 상태가 다른 화면은 `${param.state}` 로 분기한다. 예) `내 이사 ?state=empty`
- DB 연동 단계에서 더미 문구를 `th:text="${...}"` 로 교체한다.

### 앱 진입 흐름 (사용자)

`/` 접속 → 스플래시(브라우저 세션당 1회) → 로그인 전이면 `/onboarding` → 로그인(`/login/phone`) 또는 가입 완료 '시작하기' → `/login/complete` → 홈.
더보기 '로그아웃' → `/logout` → 온보딩. 화면 개발 단계의 로그인은 세션 표시만 남기며, DB 연동 시 실제 인증으로 바꾼다.

| 확인용 URL | 용도 |
| --- | --- |
| `/onboarding?splash=hold` | 스플래시를 사라지지 않게 고정 |
| `/onboarding?splash=1`, `/?state=none&splash=1` | 스플래시를 다시 재생 |
| `/?state=guest` | 비회원 홈 (로그인 없이 볼 수 있는 유일한 화면) |
| `/login/complete` | 로그인 상태로 만들기 (그 뒤 `/?state=...`, 회원 화면 확인) |

**비회원 접근 차단**: 로그인하지 않으면 회원 전용 화면(`/move`, `/quote`, `/chat`, `/more/**`, `/notifications`, `/estimates/**`, `/reservations/**`)은 `/login`(로그인 방법 선택)으로, 비회원 홈 외의 홈 상태는 `/onboarding` 으로 보낸다 (`WebConfig` · `LoginCheckInterceptor`). 비회원 홈의 하단 탭은 홈 외에는 `/login` 으로 연결된다. 로그인 없이 템플릿만 확인할 때는 `/dev/...` 미리보기를 쓴다.

## 7. 확인 방법

- `gradlew bootRun` 후 http://localhost:8080 접속. local 프로필은 템플릿·정적 파일을 `src`에서 직접 읽으므로 **HTML/CSS/JS 수정은 새로고침만 하면 반영**된다 (Java 수정은 재시작 필요).
- 컨트롤러 없이 템플릿만 확인: `http://localhost:8080/dev/<템플릿 경로>?state=...` (local 전용)
- 브라우저 개발자도구에서 기기 크기를 430 × 932(사용자) / 430 × 874(관리자)로 맞춰 캡처와 비교한다.
