# house-01 영상: AI 결과 · 정답 · 대표님 기준 맞추기 (2026-11-24)

목표는 **대표님이 방문 견적으로 낸 값(이 집 7톤, 약 55㎥)에 AI 결과를 맞추는 것**이다. 한 집에만 맞추면 다른 집에서 틀리므로, 바꾼 규칙은 집 고유 정보가 없는 **일반 규칙**만 쓴다.

- 영상: `기타/3_집영상_사람장면제외.mp4` (11.5MB, 약 1분 12초)
- 정답: `기타/정답목록/house-01-noperson.csv` (사람이 영상을 보고 기록, 품목표 품목 75개 + 표에 없는 물건 5개)
- 대표님 기준: `기타/통화정리본(기준).md` — 1톤 = 10㎥, 5톤 = 35㎥, 물품 부피 × 적재계수 2.0, 5톤 채우고 남으면 1톤 2대 또는 1대

## 1. 기준선: 정답대로 세면 대표님 견적이 나온다

| | 값 |
|---|---|
| 정답 물품 부피 (품목표 기준) | 25.3㎥ |
| × 적재계수 2.0 | 50.6㎥ |
| 트럭 조합 | 5톤(35) + 남은 15.6 → 1톤 2대 = **7톤** ✔ 대표님 견적과 같음 |

→ 계산식(적재계수 · 트럭 조합)은 대표님 기준과 맞다. **AI 가 정답만큼 세느냐**가 남은 문제.

해석

1. **모델이 가장 크다.** 예비 모델(3.5-flash)은 규칙 · 프레임을 바꿔도 재현율 40%. 혼잡할 때 조용히 예비 모델로 넘어가면 톤이 2단계 낮게 나온다 → 예비 모델 결과에는 "다시 분석 권장" 경고를 붙였다.
2. **프롬프트 v3 효과가 크다** (A → B2: 재현율 68% → 85%, 이사박스 22 → 33, 냉장고 중복 해결, 서랍장 2 → 8).
3. **초당 2프레임이 마지막 차이를 메웠다** (B2 → C: 6톤 → 7톤). 다만 1회뿐이고 입력 토큰 +64%, 시간도 늘어난다.
4. AI 는 거의 **덜 세는 쪽으로** 틀린다(정밀도 94~96%로 높음, 재현율이 낮음). 그래서 톤이 낮게 나온다.

## 4. 고객 · 관리자에게 보이는 값

고객 확인 화면은 AI 결과에서 품목명 · 크기 · 개수 · 확인 필요를 받아 그린다. 지금 앱 품목표(`request.ItemCatalog`)의 부피는 화면 시안용 임시 값이라 비교 대상이 아니고, 붙일 때는 기준표(나중에 `TBL_ITEM_SPEC`) 부피를 쓴다.
테스트 화면의 "고객 · 관리자에게 전달될 값"(기준표 부피)과 [고객 화면으로 보기](기준표 부피로 2단계 미리보기, 제출 · 저장 없음)로 확인한다.
- 미매핑 품목은 AI 가 본 이름 그대로 넘어가므로, 고객 앱 품목 목록에 없는 이름은 "(앱 목록에 없음)"으로 표시해 둔다.
